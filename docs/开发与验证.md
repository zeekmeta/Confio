# 开发与验证

面向修改 Confio、验证 NuGet 交付和维护发布的开发者。日常应用用法见[使用指南](./使用指南.md)，交互演示见 [ConfioSample](../samples/ConfioSample/README.md)。

## 环境要求

本仓库使用 .NET 10 SDK 构建。运行库与模型类库面向 `net462;net47;net471;net472;net48;net481;net8.0;net10.0`，真实消费者逐一以表中六个 Framework 目标及 .NET 8 / 9 / 10 验证资产选择与行为，Avalonia Sample 保持 .NET 10。生成器的 `netstandard2.0` 只服务编译器加载，不交付 Standard 运行库。完整矩阵需安装相应运行时和 Framework targeting pack；本机 Framework 消费运行于 Windows x64、Framework 4.8.1 宿主。用户曾回传 Windows 7 SP1 x64 下原始 Framework 4.6.2 至 4.8 的完整消费者与密文互读日志；既有证据不等于当前候选已在原始宿主复验，实际边界见[设计第 8.1 节](./设计方案.md#81-独立交付边界与当前状态)。

Framework 使用 SDK 风格项目、`PackageReference` 和 C# 12。SDK 自动处理 .NET Standard 依赖所需的兼容程序集与绑定重定向，包传递 `record/init` 所需的编译期辅助类型，应用无需手写兼容源码。Framework 4.6 / 4.6.1 及 .NET 5 / 6 / 7 不在当前范围；不通过压制依赖目标警告或 AOT 警告扩大承诺。

Linux 验收入口在 WSL 2 的 Ubuntu 24.04 x64、ext4 中运行，覆盖 .NET 8 / 9 / 10 的 JIT 与 Native AOT、自动文件密钥、原生接入及多进程更新。当前改动的实际通过情况和未验证边界统一记录在[设计第 8.1 节](./设计方案.md#81-独立交付边界与当前状态)，不以构建通过替代平台运行。

## 构建与测试

以下命令从仓库根目录执行。

通用行为测试使用夹具自己的 AES 密钥或隔离密钥文件；自动 AES 的 Windows 密钥包裹会调用 DPAPI。替换失败测试在 Windows 使用文件共享限制，在 macOS 对测试私有文件临时设置用户不可变标记并在结束时恢复；其他平台明确跳过对应专项测试。完整消费者执行当前平台的默认保护，macOS / Linux 无需桌面密钥设施，Linux 脚本为默认密钥隔离 XDG 目录：

```powershell
dotnet run --project tests/ConfioConsumer/ConfioConsumer.csproj -c Release -f net10.0 -- encryption
dotnet test tests/ConfioTests/ConfioTests.csproj -c Release --filter FullyQualifiedName~ProtectionTests
```

```powershell
dotnet build Confio.sln -c Release
dotnet test tests/ConfioTests/ConfioTests.csproj -c Release --no-build
dotnet run --project tests/ConfioConsumer/ConfioConsumer.csproj -c Release -f net462 --no-build
dotnet run --project tests/ConfioConsumer/ConfioConsumer.csproj -c Release -f net8.0 --no-build
dotnet run --project tests/ConfioConsumer/ConfioConsumer.csproj -c Release -f net9.0 --no-build
dotnet run --project tests/ConfioConsumer/ConfioConsumer.csproj -c Release -f net10.0 --no-build
```

编码行为可单独执行 `dotnet test tests/ConfioTests/ConfioTests.csproj -c Release --filter FullyQualifiedName~EncodingTests`。真实消费者默认包含 Unicode BOM、GBK、`Encoding.Default`、明文自动保护、失败保留文件及原生读取视图；同一场景随 Framework、现代 JIT 和 AOT 验收运行。Sample 的 `--verify` 还检查编码选择、文件预览与 GBK 保存失败，入口见其 README。

## 本地候选包

从当前源码构建候选包：

```powershell
dotnet pack src/Confio/Confio.csproj -c Release -o artifacts/packages
```

通过现有隔离脚本验证该目录中的包，无需改动机器级包源：

```powershell
./eng/Verify-Package.ps1 -Source ./artifacts/packages -NativeAot
```

版本以 `Directory.Build.props` 为准；开发候选包不覆盖已经分发的版本。脚本使用独立缓存和包源映射，避免同版本远端包或本机缓存影响结果。交互体验可以直接运行仓库中的 Sample。

## 隔离包验证

候选包验收脚本建立独立 feed、缓存和仅消费候选包的工程，检查八个运行库资产与依赖组、九种应用目标的资产选择、跨项目模型及生成器交付。消费路径覆盖四种格式、同步异步读写、校验、`record/init` 默认值与更新、通知、DI / Configuration / Options / Host、保护与多进程协调；还验证 Framework 与现代 .NET 双向读取同密钥 AES 密文。加上 `-NativeAot` 后发布并运行 .NET 8 / 9 / 10 的 Windows x64 Native AOT，需要安装 Visual Studio C++ 桌面工具和 Windows SDK：

```powershell
./eng/Verify-Package.ps1 -NativeAot
```

指定 `-Source` 时验证该源中与 `Directory.Build.props` 版本一致的现有包，不重新打包。脚本仍使用独立缓存和包源映射，并检查实际下载来源；源可以是本地目录或 NuGet 服务地址。该版本发布后可进行远端消费验收：

```powershell
./eng/Verify-Package.ps1 -Source https://api.nuget.org/v3/index.json -NativeAot
```

## Linux 与 WSL

Linux 通过 [Verify-LinuxPackage.py](../eng/Verify-LinuxPackage.py) 消费同一候选包。环境需要 Python 3 和 .NET 10 SDK；JIT 消费者按各目标独立发布，不需要额外安装系统运行时。Native AOT 另需平台编译工具链（Ubuntu 的 `clang`、`zlib1g-dev`）。脚本不安装运行环境，隔离包缓存与 XDG 用户目录，并设置不可用的桌面总线，验证保护无需桌面授权；日志与产物保留在输出目录。

```bash
python3 eng/Verify-LinuxPackage.py \
  --package artifacts/packages/Confio.1.0.0.nupkg \
  --native-aot
```

WSL 可用 `--output` 指定 Linux 文件系统上的产物目录。脚本覆盖完整现代 JIT/AOT 消费、自动密钥同步异步访问、跨文件并发首次创建、重启后读取、文件权限、坏钥和缺钥时数据保留，以及等待密钥文件锁时的取消。`--portable-input` 可读取 Windows 验收的 `portable` 目录；Linux 生成的密文也可由 Windows 消费者通过 `encryption read <path>` 反向验证。

## Native AOT 消费者

源码消费者也可以单独发布；该验证项目在 .NET 8 / 9 / 10 指定 RID 时启用 Native AOT：

```powershell
dotnet publish tests/ConfioConsumer/ConfioConsumer.csproj -c Release -f net10.0 -r win-x64 -o artifacts/aot/net10.0
./artifacts/aot/net10.0/ConfioConsumer.exe
```

消费者和测试默认使用隔离临时目录，失败返回非零退出码。候选包验收在本次产物目录下执行文件读写，以覆盖工作区所在文件系统；候选包与发布结果位于 `artifacts/`，不提交 Git。Framework 的禁止反射开关由测试程序的 `App.config` 设置，现代 .NET 使用运行时配置；应用无需设置这些验收开关。矩阵之外的运行时按明确需求再扩展，平台证据见[验收状态](./设计方案.md#81-独立交付边界与当前状态)。

## 文件系统验证

真实消费者可以在指定文件系统上验收，始终在给定根目录下新建独立子目录，结束时只清理本次子目录。该入口同时验证四种格式的同步异步保存和多进程更新，并在 JSON / YAML 路径验证连续替换、中文与保护值、已有读取句柄：

```powershell
dotnet run --project tests/ConfioConsumer/ConfioConsumer.csproj -c Release -f net10.0 -- --directory ./artifacts/file-verification
```

Native AOT 消费者支持同样的 `--directory` 参数。同包进程间的协作锁竞争会等待释放，异步入口接受现有取消令牌；权限和路径等真实错误直接报告。取得锁后的文件替换对 Windows 短暂占用做有上限的重试，持续失败仍报告错误；两者的等待、重试与取消边界见[文件提交契约](./设计方案.md#43-并发与外部编辑)。

## 发布

版本由 `Directory.Build.props` 维护，发布说明维护在 [CHANGELOG](../CHANGELOG.md)。发布前选定未分发的新版本，更新中英文 README 的安装命令和变更说明，提交准备发布的内容。README 会原样进入包，示例必须与该版本 API 一致；已发布版本不覆盖。

发布由 [GitHub Actions 工作流](../.github/workflows/release.yml) 执行：`main` 推送和 Pull Request 只运行构建、测试与包验收；`v` 开头的版本标签在验证通过后发布。标签必须与工程版本一致，例如 `v1.0.0` 对应 `1.0.0`。Windows 生成并验证包，Linux 下载同一份包验证，发布任务直接使用该产物，不重新打包。

公开安装入口为 [NuGet.org](https://www.nuget.org/packages/Confio)。首次发布前，在 nuget.org 设置[受信发布](https://learn.microsoft.com/nuget/nuget-org/trusted-publishing)，不需要本机或 GitHub 保存长期 NuGet API key：

| 配置 | 值 |
| --- | --- |
| Repository Owner | `zeekmeta` |
| Repository | `Confio` |
| Workflow File | `release.yml`，不包含目录 |
| Environment | `release` |
| Package pattern | `Confio` |
| 发布范围 | 允许创建新包和发布该包的新版本 |

GitHub 仓库的 `NUGET_USER` 变量填写具有相应发布权限的 nuget.org 用户名，不是邮箱或 NuGet `Authors` 字段。工作流通过 OIDC 换取短期凭据，仅发布任务具有 `id-token: write` 权限。

仓库还需配置机密 `MIRROR_NUGET_SOURCE` 和 `MIRROR_NUGET_API_KEY`，分别保存镜像地址和密钥，不写入源码或公开安装说明。工作流同时屏蔽日志中的镜像主机名，避免包源解析后的地址泄漏；两处上传同一份包。若一次发布只有部分源成功，重新运行失败的发布任务即可，已存在的版本会跳过。

nuget.org 可能需要时间完成验证与索引。可安装后，使用上面的远端包验证命令确认来源、资产选择、生成器和实际运行，并用 Sample 验证发布包。nuget.org 会对包添加仓库签名；下载后的包可验证签名及包内内容，不能仅因整个归档的 SHA-256 改变就判定包内容不一致。发布成功后记录 CHANGELOG 日期。不要移动已经发布的版本标签。
